# Сценарий показа

Около восьми минут. Подготовка: развернуть стенд с демо-данными (`npm run seed` или `docker compose --profile demo run --rm seed`), открыть приложение под менеджером (`manager@zapas.local`) и в соседнем окне терминала держать наготове `npm run emulate -- --speed 3`.

1. **Обзор.** Деньги под угрозой, просрочка, остатки по срокам, дефицитные ингредиенты за месяц. Сказать, что цифры считаются по партиям, а не по продуктам в целом.

2. **Остатки и партии.** «Остатки» → открыть молоко: несколько партий с разными сроками, оставшееся время по каждой, расход по дням и график прогноза спроса на 14 дней (день недели, праздники, погода). Партии расходуются от ближайшего срока.

3. **Поставка.** «Операции → Приход»: строка с молоком, срок хранения подставляется из карточки. Показать, что то же самое делает `POST /documents/receipts` со `shelfLifeDays`.

4. **Заказ гостя и отказ.** «Операции → Заказ гостя»: борщ × 200. Система отклоняет заказ целиком и называет, какого ингредиента и сколько не хватает. Тот же заказ на 2 порции проходит, ингредиенты списываются.

5. **Стоп-лист.** Блюдо появилось в стоп-листе с причиной. Ниже «Прогноз стоп-листа»: какие блюда остановятся в ближайшие часы и сутки и из-за чего.

6. **Горячие предложения.** Приоритет блюд по сроку ингредиентов, пояснение, сколько порций продать. Принять поставку короткосрочного продукта и показать, как список перестраивается.

7. **Живое обновление.** Запустить `npm run emulate -- --speed 3`. Панель, остатки и стоп-лист меняются без перезагрузки, в терминале видны поставки и заказы, часть заказов отклоняется. В шапке индикатор «Обновляется сразу».

8. **Рейтинг поставщиков и потери.** «Поставщики»: оценки A, B и C по выполнению заказов, срокам, свежести и порче, потери по причинам. На обзоре «Спасено уценкой» и «Дефицитные ингредиенты».

9. **Журнал HACCP.** Замеры температуры, просроченная точка и открытое отклонение, запись корректирующего действия, бракераж, выгрузка для проверки.

10. **Автоматизация.** Параметры → автосписание просроченного. Telegram: меню кнопок, `/hot`, `/subscribe`, скидка из `/risks` кнопкой с подтверждением.

11. **Касса и 1С (три минуты).** Заранее: `npm run emulate:onec`, затем `npm run emulate:setup` (в `apps/server/.env` должно быть `EXCHANGE_ALLOW_HOSTS=127.0.0.1`). «Администрирование → Кассы»: подключить кассу, показать образец чека и «Проверить». Запустить `npm run emulate:pos -- --key … --vendor evotor`: чеки списывают остатки, чек с неизвестной позицией ждёт в «Неопознанных», «Сопоставить» доигрывает его. «Учётные системы»: «Проверить» (галочки), приход в «Операциях» уходит в 1С, «Отправить в 1С» ещё раз обновляет тот же документ, а остановка имитации 1С показывает повторы и догрузку после запуска.

12. **Официант и кабинет поставщика (три минуты).** Войти официантом (`waiter@zapas.local`): блюдо из стоп-листа выбрать нельзя, оформить заказ. У менеджера «Операции → Заявки гостей»: «Взять в работу», «Выдан», обращение «разбили» с переделкой бесплатно. Кнопка «Перейти в «Отгрузку»» на экране входа ведёт в кабинет поставщика: подтвердить заказ, вернуться к менеджеру и увидеть статус. Подробный сценарий в `docs/DEMO-30.md`, блоки 5а и 10а.

13. **Надёжность и безопасность.** Роли и доступ к точкам, журнал аудита с цепочкой хэшей, работа без связи с очередью документов, проверки и тесты в CI.

О стеке Флагмана: `Запас` не заменяет iiko и 1С, а добирает то, чего им обычно не хватает: партии и сроки, стоп-лист по ингредиентам и горячие предложения. Данные идут туда, где они уже живут: чеки приходят из касс, документы уходят в 1С, приход можно отдать в iiko.

Если нужно показать нехватку быстро: `npm run emulate -- --speed 10 --pressure 0.5`.
